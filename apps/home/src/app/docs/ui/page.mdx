# @core/ui

The platform design system: CSS-variable tokens plus React components styled with Tailwind CSS v4. Everything on
this page is rendered with the real components, so toggle dark mode from the user menu to see the tokens switch.

<InstallLine packages={["ui"]} />

## Setup

```css
/* file: web/src/app/globals.css */
@import "tailwindcss";
@import "@core/ui/styles.css";
```

Your app needs `tailwindcss` v4 and `@tailwindcss/postcss` (peer dependencies; generated apps have them).

## Server and client components

| Import | Components | Server Components? |
|---|---|---|
| `@core/ui` | `Card`, `CardHeader`, `CardBody`, `Table`, `Stat`, `Badge`, `EmptyState`, `PageHeader`, `cn`, plus everything below | ✅ Yes, including function props such as `Table` cells |
| `@core/ui/client` (also re-exported from `@core/ui`) | `Button`, `Spinner`, `Input`, `Select`, `Dialog` | Render them anywhere; event handlers need a Client Component |

Import everything from `@core/ui`. The package keeps the client boundary in the right place for you.

## Tokens

Use token utilities instead of raw colours, so themes (and future tenant branding) just work.

| Utility | Use for |
|---|---|
| `bg-bg` · `bg-surface` · `bg-surface-muted` | Page, cards, subtle fills |
| `text-fg` · `text-fg-muted` | Primary and secondary text |
| `border-border` | All borders and dividers |
| `bg-brand` · `text-brand` · `bg-brand-subtle` · `text-brand-fg` | Primary actions, links, selection |
| `text-success` · `text-warning` · `text-danger` (and `bg-*/10`) | Status |
| `rounded-card` | Cards, panels, dialogs |

<div className="my-5 grid grid-cols-2 gap-2 sm:grid-cols-4">
  {["bg-bg", "bg-surface", "bg-surface-muted", "bg-brand", "bg-brand-subtle", "bg-success", "bg-warning", "bg-danger"].map((c) => (
    <div key={c} className="overflow-hidden rounded-lg border border-border">
      <div className={`h-12 ${c}`} />
      <p className="bg-surface px-2 py-1 font-mono text-[11px] text-fg-muted">{c}</p>
    </div>
  ))}
</div>

## Table

`Table` is a Server Component, so `cell` renderers can live right next to your data fetching.

<Example code={`<Table
  caption="Orders"
  rows={orders}
  rowKey={(o) => o.id}
  empty={<EmptyState title="No orders" />}
  columns={[
    { key: "id", header: "Order", cell: (o) => o.id },
    { key: "status", header: "Status", cell: (o) => <Badge tone="success">{o.status}</Badge> },
    { key: "total", header: "Total", align: "right", cell: (o) => money(o.total) },
  ]}
/>`}>
  <Card className="w-full">
    <Table
      caption="Example orders"
      rows={[{ id: "ORD-1006", status: "pending", total: "$1,200.00" }, { id: "ORD-1001", status: "shipped", total: "$1,156.00" }]}
      rowKey={(o) => o.id}
      columns={[
        { key: "id", header: "Order", cell: (o) => o.id },
        { key: "status", header: "Status", cell: (o) => <Badge tone={o.status === "shipped" ? "success" : "warning"}>{o.status}</Badge> },
        { key: "total", header: "Total", align: "right", cell: (o) => o.total },
      ]}
    />
  </Card>
</Example>

  <div className="grid w-full gap-4 sm:grid-cols-3">
    <Input label="Customer" placeholder="Northwind Traders" hint="As it appears on the invoice" />
    <Input label="Quantity" type="number" defaultValue={0} error="Must be at least 1" />
    <Select label="Status" options={[{ value: "paid", label: "Paid" }, { value: "shipped", label: "Shipped" }]} />
  </div>

Both take `label` (required), `hint` and `error`, wire up `id`, `aria-invalid` and `aria-describedby` for you,
forward refs, and accept the native element's props. `Select` also takes `options`.
